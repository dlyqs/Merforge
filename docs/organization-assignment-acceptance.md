# 组织任务分配与接收验收

当前主流程是分配、员工接受、员工主动使用 Agent 或自行执行、成果汇报、原下发人审批。设备准备与领取流程已移除。本文记录用户侧待验步骤，工程覆盖不等于可见产品验收。

## 用户三机验收

A 为服务 Desktop，B 为下发人 Desktop，C 为员工 Desktop。使用独立应用数据目录和不同账号，连接同一 HTTPS 服务并人工核对证书。基础准备见[组织基础验收](organization-foundation-acceptance.md)。

| 步骤 | 操作与应观察结果 |
| --- | --- |
| 分配 | B 创建叶子任务，确认当前目标、范围、要求、版本及员工。确认分配后原子授予 C 所需项目/任务访问，创建一次接受请求和任务对话 |
| 接收 | C 可以先标已读，但状态仍待接受；明确接受或拒绝后记录答复。接受不调用模型，不执行工具 |
| 执行 | C 接受后在普通任务对话输入指令，或自行完成。界面没有设备登记、准备能力授权、领取、续租步骤 |
| 汇报与审批 | C 上传所选成果并提交摘要与目标说明，B 核对后接受或驳回。普通 Agent 和手工作业无需 Run，详见[执行验收](organization-execution-acceptance.md) |
| 断线 | 断线禁止组织写入；恢复后核对当前身份和状态。未知操作先查回执，不自动执行或重复分配 |
| 版本变化 | B 保存新计划 revision，旧分配停止推进；新版须重新分配和接受，历史答复、成果和审批保留 |
| 撤销与撤权 | B 撤销分配或 C 的任务访问后，C 不得继续任务执行或提交；重授不会复活旧分配 |
| 重启与恢复 | A 普通重启保留 accepted 状态，不要求设备领取。停服备份恢复使旧分配失效，需要重新登录、分配和接受 |
| 多客户端 | 同一员工的另一个 Desktop 可读取相同 accepted 分配，没有独占设备租约；不同账号不能借分配 ID 旁读 |
| 隔离 | 切换个人模式、组织或账号清除旧组织内容。第三方不能借搜索、计数、通知、回执或成果哈希读取未授权任务 |

每例记录构建版本、系统、任务 revision、分配状态与实际结果，不记录密码、令牌、私人目录或敏感原文。可见布局、跨机网络、休眠与 OS 凭据存储由用户实际确认。
