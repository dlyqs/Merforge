## 用户可见成果

首次安装后，用户可以进入 CLI 菜单或 GUI，连接本地服务、选择已配置仓库和明确基线、手工创建阶段/任务及验收、审阅、启动、观察、取消、核对和重试。正常使用不需要手填内部 ID、revision、snapshotHash，或借助样例脚本与数据库工具。原子命令及 JSON 导入导出保留给脚本和高级用户。

M3.1 的手工计划编辑器不调用 LLM：用户仍需要明确任务内容、改动范围与验收要求。支持当前 plan.v1 的 Mock/Human 和 plan.v2 的全代码计划，不提前承诺混合执行器代码计划。非开发用户从自然语言得到可执行计划的能力由 M4 交付。

## 交互与技术合同

1. CLI 提供目标/计划列表、新建、审阅、执行控制、结果查看、恢复处理、配置诊断及返回/退出。建议无参数且为 TTY 时进入菜单；非 TTY 必须保持可预测的帮助/退出行为，既有子命令、JSON 输出与退出码兼容。最终命令名在 Phase 1 固定，再写入使用文档。
2. GUI 提供等价的工作流程及结构化表单；JSON 为高级入口。首页真实区分 Mock、Human、Codex；修复当前“仅模拟、不调用 AI”的过期说明。此阶段不以静态聊天框冒充 LLM 规划。
3. 初次引导检测本地服务、Codex 可用性、仓库配置和干净基线；给出可操作的失败原因。CLI 可提供显式启动本地服务的操作，GUI 提供连接状态及首次启动指引。配置写入必须展示具体变更，由操作者确认；默认不修改全局 Codex 设置，不把凭证传入浏览器或写入日志。GUI 不开放任意本机路径读写接口。
4. CLI/Web 都通过 API 和同一 Runtime 控制，不各自实现调度器或直接改 SQLite。运行环境由本地操作者管理；仓库选择使用受控目录清单。若需新增配置 API，必须在 Phase 1 明确本机信任边界和可写范围，不借交互补齐扩大外部操作权限。
5. 审阅展示目标、阶段/任务、文件范围、检查内容及版本。批准与启动分开；界面内部绑定最新 revision/controlVersion。轮询不得悄悄替换用户正在审阅的版本；过期后要求重新加载。
6. 核对先展示旧尝试、进程状态、diff、文件清单和阻塞原因。显式停止核实身份的进程与接受快照并重试为不同操作；内部保存确认所对应的 hash，确认后漂移必须拒绝。不能以“一键恢复”隐藏杀进程、接管文件或新建 Attempt 的含义。Runtime resume 未开放时明确显示“创建新尝试”。
7. 保留 M3 冻结计划、独立验收、当前 Attempt 条件写入、工作区隔离和关闭等待等约束。界面取消请求不等于进程已停止；Agent 正常退出不等于任务完成。
8. 不新增 Planner、多 Agent 调度、自动修复循环、任意终端、推送/部署或企业 Pack。交互依赖按实际需要选择，不先引入新的图形框架或完整 TUI 框架。

## 验收矩阵

同一组业务场景分别从 CLI 菜单和 GUI 操作层进入；不得仅测试 Runtime 方法后宣布交互完成。

| 场景           | 必须证明                                                                        |
| -------------- | ------------------------------------------------------------------------------- |
| 首次使用       | 无配置/服务不可用时有清晰指引；配置可用后选仓库和基线，不靠脚本生成计划         |
| 建立与审阅     | 用户通过表单/问答定义阶段任务；批准不会自动启动；旧版本审阅不能作用于新版本     |
| 三阶段执行     | 模式可选择；auto_until 到界后后继零 Attempt，重启保持，显式继续后完成           |
| 真实代码结果   | 从交互入口派发 Codex，文件与独立检查可查；Mock/Human 的示例 PASS 不冒充代码通过 |
| 失败/取消/中断 | 保留旧尝试，明确区分请求取消、停止已确认和无法确认；恢复不用手填 hash           |
| 漂移与旧页面   | 用户确认之后文件或计划版本改变，操作被拒绝而不是自动接受新状态                  |
| 非交互兼容     | 既有命令、JSON 输出及退出码可用于自动化；非 TTY 不挂在菜单等待输入              |

助手遵守用户限制：不打开页面，不用 Playwright/浏览器工具、GitNexus 或子代理；本次用户明确授权交接新任务。CLI 用 PTY/按键级回归；GUI 用表单/操作逻辑与 API 集成、类型和构建检查，不能仅覆盖 API 而跳过 UI 操作绑定。视觉和实际浏览器点击列为用户可选检查，未执行如实记录，不宣称已做。真实 Codex 调用必须单列证据，环境权限缺失时明确阻塞，不用替身替代。

最终运行与改动相关的测试及 `pnpm check`、`pnpm format:check`、`git diff --check`。用户可选检查与必需自动检查分开记录，不能把“没有浏览器验证”误写成完整 GUI 体验已被人工验收。
