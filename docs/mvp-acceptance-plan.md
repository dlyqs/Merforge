# 首版真实闭环与演示候选版执行计划

本文细化[产品路线图](../ai-native-work-os-product-roadmap.md)的 **产品 Phase 8**。下文 Phase 1–8 是本计划内部编号，与路线图产品编号、已完成的 7A/7B/7C 内部编号分开。后续针对本计划说“继续”或“执行 Phase X”，先读本文及[工程概览](overview.md)，不续跑已完成计划，也不进入产品 Phase 9 的跨设备交接、费用预算或记忆治理。

## 目标、歧义检查与可行性

目标：把已经完成工程连接的个人/组织对话能力，验证为有真实模型、真实双人三机、当前平台和独立成果证据的首版演示候选版。正常模式关闭 forced，从自然 CSV 目标开始，在同一对话完成草案、调整与分配；员工在独立对话接受、委托、运行、处理人工请求、提交；原下发人验收或驳回、完成返工和必要成果汇合，核验目标后明确确认交付。

歧义检查：7C 的内部 Phase 1–10 已完成，路线图明确下一产品阶段为 Phase 8，因此本轮无需在 7B、7C 或产品 Phase 9 之间再选择。此次用户仅要求“给出下一阶段的执行计划”，不授权启动实施或产品验收；上一计划的自动执行授权不继承。采用[7C 验收交接](conversation-planning-acceptance.md)已确定的 `result.csv` + `contract.json` 作为首轮三机主样例，复用个人工作流 CSV 导出/接力案例补个人侧验收，不额外开发独立演示业务应用。

这是大型验收与缺陷收敛目标：跨 Host、原生传输、服务端事务、文件成果、真实模型及 OS/网络环境，适合分阶段执行。技术上可行，现有权威、工具和交付消费者可复用；主要风险是尚无当前候选版的真实产品证据，不能根据确定性测试预测真实模型或三机必然通过。

本期范围：证据基线、可重复的候选构建、无窗口真实模型验证、个人 Project/Bot/同机接力遗留验收、A/B/C 三机与权限故障验证、双平台发行资格、阻断这些既定行为的最小修复、演示步骤及交付判断。

范围外：Codex 新组织目标规划的能力开发、增加模型供应商、外部执行器扩容、跨设备/跨成员自动接力、共享 Runner、自动调度、自动审批/委托/提交、企业 IM、知识记忆、Linux 支持、全套升级系统重构、自动提交/推送/tag、上传更新源或公开发布。Codex 仅可展示独立 7B/设置计划已经实际验证的能力；主验收使用内建 API，不为选择 Codex 的用户暗中切到 API。

## 验收事实与证据规则

复用现有服务和业务动作，不引入第二套任务状态或组织数据库。SQLite 当前 v14、Session 当前格式和旧数据拒绝策略保持原规则；若真实缺陷需要改变持久格式，先按现有机制记录迁移范围与消费者，再实施，不能在验收脚本里私改业务库。

候选版由源码状态、构建配置、目标 OS/架构、模型/策略、构建或包摘要共同识别。同一产品结论必须能定位这些值；包含未提交修复时记录 dirty 和变更摘要，不能仅写一个未覆盖修改的 commit。证据存放位置在 Phase 1 固定；仓库文档仅保留脱敏结论和引用，不提交原始 JSONL、密钥、真实账号或整个 SQLite/备份。

用例记录可为 `passed`、`failed`、`skipped`、`not_run`，与主表的阶段状态分开。模型替身、无窗口真实模型、产品可见、平台安装、三机结果分别记录。程序不能把 skipped 或 not_run 转为 passed，不能以工程阶段 completed 代替产品准入。实测失败保留首轮记录，修复后只重跑受影响部分；涉及 shared revision、权限、协议或打包闭包变化时，明确失效哪些旧证据。

真人固定动作在自动化中仅由测试驱动明确调用，用来验证 API/Host 消费者；这不是模型获得审批能力，也不替代产品里用户亲自点击确认的证据。模型通过自然输入决定分类/提案；真实 lane 不用工具名提示、固定树预种或覆盖 classification 来制造成功。结果以权威记录、独立文件字节/哈希、未选中文件不变和私有内容隔离判断，不以模型回答关键词判断。

演示采用合成数据、隔离测试组织与可丢弃 Git 目录。负例只作用于本次测试资源；真实业务库、用户现有文件、系统防火墙与 OS 权限不自动修改。模型的实际在途动作可能产生结果，停止/撤权不承诺回滚；unknown 必须核对。

## 关键链路日志与采证

沿用 `ctx.logger`，Electron 原生层沿用 `console.info/error` 的结构化格式。以下是需要确认的长期诊断记录，不要求无差别新增日志；只有现有记录无法关联实际失败时才补最小字段。业务事件/JSONL/SQLite 仍是事实来源，诊断日志不成为第二状态机。

| 阶段/链路 | 关键观察 | 推荐标识与限制 |
| --- | --- | --- |
| Phase 2–3：发送→规划许可→模型→提案 | 输入接受、设置版本、分类、准入拒绝、实际请求/重试、保存/冲突/unknown | `component=planning/planning-model goalId operationId permitId planId planRevision generation result reasonCode` |
| Phase 3–5：分配→员工对话→Run | 单项确认、回执核对、绑定恢复、接受/委托/领取、开始/等待/恢复/停止 | `component=conversation/execution assignmentId bindingId runId operationId result reasonCode` |
| Phase 5：文件→提交→验收→最终确认 | 产物登记、提交/驳回的新版本、必要输入资格、目标观察和最终决定 | `submissionId artifactId planRevision integrationId result`；仅允许选中成果的长度/哈希 |
| Phase 6：失联/撤权/重开 | 代次、epoch、许可失效、未知结果核对、迟到结果丢弃 | 不打印每次轮询、每个 SSE 或模型 chunk |
| Phase 7：候选包→启动 | 目标平台/版本、包摘要、签名状态、payload/Host smoke、启动或恢复失败 | 配置只记录缺失字段名/稳定错误码，不记录值 |

禁止记录 key、token、验证码、证书私钥、恢复凭证、完整成员列表、真实邮箱、聊天全文、绝对私人路径、全量目录或文件字节。授权执行模型请求本身不授权上传日志。临时采证脚本只输出脱敏摘要；若为定位问题加入临时详细日志，阶段完成时移除或降级并记录位置。

## 执行规则

```text
execution mode: manual
automatic start phase: none
automatic stop phase: none
conversation relay: off
plan review: pending
execution authorization: 仅生成下一阶段执行计划，未授权 Phase 1
skill: /Users/git_local/dev-workflow-skill/SKILL.md
```

1. 本文是产品 Phase 8 的施工入口。初版写完后停在评审，不改实现、不运行模型/构建/页面；用户后续明确“执行 Phase 1”或授权具体范围才开始。上一计划的自动授权不继承。
2. 每次执行前先读本文、overview、当前用户约束、相关目录规则与 git 状态。`执行 Phase X` 本轮只执行该阶段，即使持久模式为自动也不能据此连跑；依赖未完成且不能隔离则报告依赖。
3. `继续` 先复核相关 blocked 的解锁条件；已恢复则转 in_progress，否则停在依赖 gate。没有阻塞时选首个 in_progress，否则首个 pending；已完成阶段不重跑。
4. `manual` 执行所选阶段，更新唯一主表、对应实际完成区和 overview，报告后停止。实际记录包含变更文件、执行检查、失败/跳过、偏离及下一步；未开始阶段只保留一行占位。
5. 计划已存在且用户明确要求自动完成剩余阶段时，先记录原授权再设 `auto`，自动边界均为 none；连续选择合格阶段至完成或真实阻塞，不逐阶段再次询问。
6. 用户明确要求到某阶段或连续若干阶段时，校验主表和依赖，将包含首尾的具体范围写入 `auto_until`。省略起点取当前 in_progress，否则首个 pending；数量按表中顺序换算。边界不存在、终点早于起点或跳过必要依赖时，保持原模式，只澄清实际冲突；`执行 Phase 5` 不等于“执行到 Phase 5”。
7. 自动选择下一阶段前重读状态、依赖、模式和授权范围，先标 in_progress。非阻断的用户侧待验记载后继续；需要凭据/设备/实际用户证据、新权限、重大产品选择、无法安全修复的失败或用户撤销时才停。
8. 阻塞时写明确切阶段、已完成准备、失败或缺失证据及解锁条件，保留原 auto/auto_until 和范围；用户解除后沿原授权恢复，不自动另开聊天或绕过 gate。
9. auto_until 范围内全部必要工作及要求的交付返回完成后，改回 manual、清空两边界，记录到达授权终点并停止；终点已完成不代表范围内其他阶段已完成。auto 全计划完成后也收束为 manual。不得进入产品 Phase 9 或自动发布。
10. 只有执行证据显示阶段过大、风险失控或难以安全核验时，才先更新主表、该阶段范围/验收/顺序，做最小有用拆分，通常两个子阶段，保留无关编号。原停止阶段被拆时默认映射到最后子阶段，除非用户明确只授权某子阶段。
11. Relay 默认 off，不新建聊天、worktree 或专用 executor Skill。仅在用户针对本计划明确授权后读取 `/Users/git_local/dev-workflow-skill/references/conversation-relay.md`；涉及 worktree 另读 `worktree-return.md`，先补齐授权、批次、所有权、交接记录及交付返回字段。未完成回归交付不得报告已整合。
12. 禁止自行启动页面、使用 Playwright/浏览器自动化/GitNexus；不自动创建 Agent Notes，不自动安装/索取凭据，不改真实组织数据、不提交/推送/公开发布。已明确的用户授权持续有效，例行可逆实现和检查不重复申请许可。
