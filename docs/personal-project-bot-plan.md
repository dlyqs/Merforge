# 个人项目与 Bot：产品路线图 Phase 2 开发计划

本文细化[产品路线图](../ai-native-work-os-product-roadmap.md)的 **Phase 2**。以后收到“继续”或“执行 Phase X”时，先读取本文，再依据唯一的阶段状态表执行。2026-09-24 根据用户反馈修正项目与 Bot 导航：Workspace 转为 Project，侧栏只保留 Project 和 Bot 两个并列分区，不再设置外层“个人”折叠。Desktop 可见交互和真实模型调用未由助理验收。

## 目标与可行性

交付可用的个人 Desktop 模式：项目首先用于分类和组织对话，可选绑定本地目录；私人 Bot 提供可复用的用户指定身份、工作方向与能力配置。项目可以直接创建普通对话，也可以选择 Bot 创建对话。对话可以在项目之间、Bot 之间变更当前归属；同一 Session 始终保留对话及归属变更历史，各入口引用同一记录。后续请求使用当前项目与当前 Bot 的现有配置；两类记忆即使为空，项目和 Bot 也必须正常工作。用户继续控制模型和凭据配置。

旧 Workspace 中保存的目录、名称和会话归属迁入 Project。Project 自身持有稳定 ID 和可选本地目录；目录路径不充当项目 ID。Bot 是与 Project 并列的另一分区，二者引用同一 Session。现有设置、凭据、模型选择、Session 事件及 Agent preset 继续复用，无需另建一套 Session 存储或模型设置系统。

[基础裁剪计划](desktop-agent-foundation-pruning-plan.md)的 Phase 7 仍为 `in_progress`，当前未提交的 Desktop 清理改动需另行完成针对性验证。用户于 2026-09-24 明确取消 macOS/Windows 安装验收要求，并报告本地模型已能正常交互。这是用户报告的结果，不等同于助理运行过真实模型测试；未验证的浏览器、计算机操作、恢复和安装行为仍应如实标注。基础裁剪计划的剩余收尾不阻塞本计划的规划和实现。

## 范围、假设与约束

- **范围内：**独立于目录的个人 Project、可不选 Bot 的项目对话、用户指定身份的 BotProfile、Session 当前归属及变更历史、项目间和 Bot 间移动、模型/Skill/工具默认配置、双入口、复用现有模型设置、重启后保持数据，以及针对性验证。
- **范围外：**项目/Bot 记忆的自动总结、持久写入、检索和编辑界面，任务实体及专属视图、组织身份、共享项目、WorkGraph、跨对话任务接力、向量检索、外部 Agent 适配器、新模型供应商，以及公开 Web/CLI 入口。本阶段不为未来记忆或任务建立没有当前消费者的空服务。
- **项目身份：**`ProjectId` 是项目唯一身份。项目可以不选本地目录；选中目录时，Project 直接保存规范化路径。迁移旧 Workspace 时保留其稳定 ID、名称、目录和会话关联，迁移完成后删除旧目录分组记录。项目删除不删除目录或 Session。
- **导航层级：**侧栏直接展示“项目”和“Bot”两个并列标题，每个标题下的对象行可展开其对话。没有第三个总分区，也不展示 Workspace 列表。两种对象行沿用原工作区列表的行高、缩进、悬停操作与会话状态表达，仅图标和对象专属操作不同。
- **会话身份：**`SessionId` 不随拖动改变。一个 Session 有可选的当前 `ProjectId` 和可选的当前 `BotId`，两者不是 Session 的永久所有者。项目可以不选 Bot 创建普通对话；Bot 入口创建的对话也可以没有项目。项目间、Bot 间移动更新当前归属，并把前后身份记录在同一 Session 中。项目与 Bot 入口只索引当前归属，读取同一事件日志、标题和运行状态，不创建副本。是否提供“移出 Bot 到普通对话”的直接操作，可在 Phase 1 结合 UI 定稿。
- **上下文变更：**每次归属变化都记录来源、目标和发生位置，并在后续模型上下文中提供当前归属及必要的变更说明。从下一次获准的请求起，只应用当前项目元数据与当前 Bot 的用户指定配置；过去的 Session 消息和请求记录不追溯改写。未来加入记忆后，只读取当前归属对象的记忆，不按旧归属检索。用户接受旧对话历史可能影响移动后的继续效果，本阶段不承诺消除这种影响。
- **删除语义：**删除 Project 或 Bot 不删除 Session 及其归属历史。当前引用如何转成普通对话、未分组对话或已删除对象标记，由 Phase 1 对照现有归档/删除规则定稿；不能直接抹掉过去的归属事件。
- **未来的记忆设计方向：**项目即使没有记忆，也是一种对话分类分区。后续可由 Agent 根据关键词触发项目目标、架构和规范等内容的总结。Bot 的用户指定身份保存在 Profile 中并优先于学习结果；后续可自动为其对话生成简要摘要，逐渐归纳常处理的工作和流程。项目事实归项目，Bot 的跨项目经验归 Bot；Skill 保持独立的版本化资源。具体触发、摘要质量、写入、纠错与检索规则在后续阶段单独测试优化，本阶段允许两类记忆始终为空。
- **模型：**复用 `ui-settings-models`、凭据服务和 `ui-model-selection`。Bot 默认模型只能引用已配置且允许使用的路由；BotProfile 不存 API key。
- **产品与验证：**Electron 是唯一用户入口。遵守 Host/Client 分层、UI 文案本地化、现行 Session 格式、跨边界品牌化 ID 和 package 能力接口。按用户要求，不启动页面，不使用 Playwright、浏览器自动化或 GitNexus；用户可自行检查可见的 Desktop 行为。

## 阶段详情

### Phase 1 行为决定

`Project` 保存独立 ID、名称、说明和可选规范化目录。创建 Session 时直接读取 Project 的目录作为默认 `cwd`，不再传入或写入 Workspace 归属；分叉继承归属事件，不附着 Workspace。Session 的 `cwd` 是创建时的目录事实；后续移动项目只改变分类，不改写 `cwd` 或扩张文件访问范围。旧 Workspace 记录转为 Project 后，其原有 Session 通过归属事件关联到新 Project；归档与置顶仍作用于同一 Session。

`Session` 的 `personal/affiliation` 事件记录每次完整的当前 `{ projectId?, botId? }`、前值和操作来源；投影从同一事件序列重建当前值和历史。创建普通项目对话写入项目 ID 且 Bot 为空；项目里选择 Bot 时两者都写入；独立 Bot 对话只有 Bot ID。移动可分别修改项目或 Bot，也可显式清空任一归属，因此“移出 Bot 到普通对话”是直接操作。无变化不追加事件。分叉继承截点时的归属事件，再由分叉后的新事件独立演进；归档仅影响可见状态，不清空归属。删除 Project/Bot 会为当前引用它的 Session 追加清空归属事件，保留旧事件及对象的名称快照；即使 Session 暂时无法打开，旧事件仍可解释，当前引用视作已删除对象并在下次写入前清理。删除对象不删除 Session。

请求读取当前归属事件和当前 Project/Bot 记录；Bot 用户指定身份、工作方向和允许能力优先于今后可能出现的学习摘要。当前没有项目或 Bot 记忆。归属变化和 Profile 编辑只影响之后获准的请求；当次实际进入模型的项目/Bot 文本由 Session 的 `system/message` 记录，已选择的模型和工具清单由 `request/header` 记录，归属变化另有事件。旧消息、旧请求和旧事件不回写；旧历史可能继续影响模型。Session 显式模型选择优先于 Bot 默认模型，Bot 默认模型优先于全局默认模型；不可用路由报错。Bot 允许工具和 Skill 在实际执行入口检查；没有 Bot 时使用现有能力规则。

`api-session-controller` 拥有普通 Session 的创建、分叉、恢复和模型选择，`agent-preset-registry` 拥有预设组合，`ui-model-selection` 调用 Session 选择接口，设置和凭据服务保管模型配置与密钥，Host Controller 经 Typert 暴露数据，Client 只接收投影。基础裁剪计划的 Phase 7 仍在执行，未验证项保持未验证；本计划不改写其状态。

### Phase 1：数据与行为定稿

**目标：**在增加存储或 UI 之前，把路线图中的个人模式行为落实为明确的数据归属和状态变化规则。

**预计涉及：**本文、`docs/overview.md`，以及 Workspace、Session、preset、模型相关源码和 package 文档；仅在现有文档无法容纳决定时新增简短决策记录。

**验收清单：**

- [x] 梳理旧 Workspace 归属、Session 创建/分叉/归档、Agent preset、模型选择、凭据存储和 Host/Client API 的责任方；将目录归入 Project。
- [x] 定义项目普通对话、项目中选择 Bot 创建对话、Bot 对话加入或移出项目、项目间与 Bot 间移动、分叉继承和删除后的行为；明确“移出 Bot 到普通对话”是否作为直接 UI 操作。
- [x] 确定归属事件和当前归属的单一权威来源，以及模型如何获得当前归属与必要的历史说明；旧消息保留，不承诺移动后继续效果等同于新对话。
- [x] 区分 Bot 的用户指定身份与未来 Agent 学到的简要摘要，明确用户指定身份优先；确认项目与 Bot 的记忆为空时所有当前流程仍可运行。
- [x] 区分 Session 中应记录的模型可见配置与可修改的私人 Profile 引用，确保当前格式会话可重新打开并重建请求。
- [x] 核对基础裁剪剩余改动与本阶段接口的重叠范围；不把用户免验的安装项目写成已通过。

**助理侧验证：**源码/API 审阅、旧 Workspace 与 Session 的针对性现有测试、依赖映射检查。**用户侧人工检查：**若 Bot 编辑/删除或分叉语义与上述默认假设不同，审阅该决定。**依赖：**当前基础代码；基础裁剪收尾可并行进行。**实际完成记录：**2026-09-24 初版曾把 Project 与 Workspace 设为两个身份；该决定已按用户反馈撤销，以上修订后的行为规则为准。基础裁剪状态未改，安装验收仍按用户免验处理。

### Phase 2：Project、BotProfile 与 Session 关联持久化

**目标：**分别保存项目和私人 Bot，让普通或 Bot 对话在项目/Bot 间移动而不复制 Session 数据。

**预计涉及：**Project 与 Bot Service Definition/Provider、个人存储域、旧目录记录迁移、Host Controller/API 投影、Desktop 组合和针对性测试。

**验收清单：**

- [x] BotProfile 可创建、列出、重命名、编辑、删除并保存用户指定身份和当前能力配置，使用稳定的品牌化 ID；非法字段被拒绝，重启后数据仍在。
- [x] Project 可不绑定目录而持久存在；选中本地目录时直接保存规范化路径，不以路径作为 `ProjectId`。
- [x] Session 当前项目/Bot 与每次变更历史以单一权威机制持久化；移动不产生重复 Session，重启后当前归属和历史一致。
- [x] 删除、分叉与归档遵循 Phase 1 定稿规则；删除项目或 Bot 后，已有对话及过去的归属事件仍可解释。
- [x] Project 与 Bot 数据保存在个人存储中，凭据仍只进入现有凭据服务。

**助理侧验证：**存储恢复及生命周期、API 非法引用、相关 Session 重开、产品可见插件的真实组合测试和针对性 typecheck。**用户侧人工检查：**本数据阶段无必需项。**依赖：**Phase 1。**实际完成记录：**2026-09-24 完成。新增 `packages/workspace/personal-project`、`personal/affiliation` 投影、Session 创建/移动/删除/分叉 Host 路径和 Web bundle Host 行；更新持久化目录及 TypeScript 依赖。测试覆盖存储重开、事件前缀重建、对象删除、并发删除阻止新引用、Loader 组合及模型非法路由；Host 与相关包构建通过。下一阶段为 Phase 3。

### Phase 3：项目上下文、Bot 运行配置与默认模型

**目标：**让当前项目元数据与当前 Bot 的用户指定配置影响实际 Agent 工作，移动之前的请求保持原样；两类记忆为空时仍能运行。

**预计涉及：**Agent preset/请求入口的 Bot 消费方、现有模型设置与选择接口、工具/Skill 的实际授权入口及相关测试和文档。除非现有扩展点确实不足，不修改 `agent-loop`。

**验收清单：**

- [x] Bot 默认模型只解析到已配置、可用的路由；Session 显式选择的优先级有明确规则，无法使用时显示错误，不静默回退。
- [x] Bot 指令和允许的 Skill/工具在实际执行入口生效，直接调用或其他入口不能绕过限制。
- [x] 每次项目或 Bot 变更后，仅之后的请求获得当前项目元数据、当前 Bot 的用户指定身份与配置以及获准资源；旧 Session 消息继续保留。
- [x] 模型能从已记录的归属事件和当前上下文了解必要的转移历史；每次实际进入请求的内容均可从 Session 重建。
- [x] 没有项目或 Bot 记忆时，普通项目对话、独立 Bot 对话和两者结合的对话均正常运行；不为未来的自动学习预置无消费者的写入服务。
- [x] Profile 编辑只影响之后获准的请求，不改写旧请求，也不泄露 API key。

**助理侧验证：**真实组合下的模型请求、执行入口拒绝、Session 重放/重开、不可用模型路由测试；有密钥时可补真实 API smoke。**用户侧人工检查：**可自行在 Desktop 中选择模型并进行一次受控 Bot 对话；该结果不写成助理测试。**依赖：**Phase 2。**实际完成记录：**2026-09-24 完成。运行时插件按当前归属渲染 Project/Bot 文本与最近变更；Session 显式模型优先于 Bot 默认，Bot 默认优先于全局默认；工具在模型清单、PTC SDK、查找和执行入口按当前 Bot 过滤，Skill 在目录、加载、显式调用及 Session 列表过滤。组合测试、针对性类型检查、Host 打包、JSDoc、Cordis 配置、包依赖与局部 lint 通过；真实 API smoke 和用户侧 Desktop 可见检查未运行。全仓 invariant 门禁仍因三个未修改的 `session-format*` README 缺少既有说明而失败。Phase 4 是下一阶段。

### Phase 4：项目与 Bot 双入口

**目标：**让两个入口通向同一个 Session，显示一致的关联和状态。

**预计涉及：**`packages/client/ui-workspace`、侧边栏/导航 slot、Bot UI 插件、本地化字典、Host follow 投影和针对性 Client 测试；复用现有模型设置界面。

**验收清单：**

- [x] 侧栏只有 Project 与 Bot 两个并列分区；不显示 Workspace 列表或额外的“个人”折叠层。
- [x] 项目入口展示当前归属该项目的对话及现有运行/待处理/完成状态，并标明当前 Bot；Bot 入口通过同一 `SessionId` 列出当前归属该 Bot 的对话。普通项目对话无需 Bot 标记。
- [x] 从任一入口打开关联 Session，不复制消息、Run、归档或未读状态；刷新和重启后两处仍引用同一记录。
- [x] 可在项目中直接创建普通对话，也可选择 Bot；可把独立 Bot 对话拖入项目、在项目间移动或在 Bot 间移动。界面显示当前归属与归属历史，文案进入本地化字典。
- [x] Project/Bot 创建与编辑有可访问的操作；删除对象后旧对话仍可找到，归属历史仍可解释。

**助理侧验证：**纯 Client/Host 投影测试、同 ID 状态更新、归档/删除/重启、locale 与可访问性静态检查、typecheck 和前端 build。**用户侧人工检查：**可自行检查 Desktop 双入口和编辑流程；助理不打开页面或运行 Playwright。**依赖：**Phase 2–3。**实际完成记录：**2026-09-24 完成。新增 `packages/client/ui-personal` 与 `sidebar.personal`：Project/Bot 列表从同一 Session catalog 和归属投影索引，同一 ID 打开同一会话；支持创建、编辑、删除、普通或 Bot 对话创建、拖动及选择器移动、历史与删除后未归属会话。Client 创建参数透传到 Host，重连时刷新个人记录。117 个相关 Client/Host 测试、针对性类型检查、局部 lint、本地化门禁和前端构建通过。全量 `test:gui` 曾因本阶段新增的启动 RPC 与侧栏快照失败，已改为展开时读取并更新快照；复跑相关用例通过。另有未修改的 Settings Account 组合用例因该插件未进入当前 Web bundle 失败，Settings General 两个用例缺失预期插件或超时；不归因于本阶段。Desktop 可见操作由用户自行检查，未运行浏览器或 Playwright。下一阶段 Phase 5。

### Phase 5：Phase 2 集成验收

**目标：**用可复核证据收尾路线图 Phase 2 的持久化、空记忆下的模型使用及 Desktop 展示行为。

**预计涉及：**集成测试/夹具、package README、`docs/overview.md`、本文；只有证据支持时才更新路线图状态。

## 后续执行规则

执行模式：`manual`。自动开始阶段：无。自动停止阶段：无。跨对话自动接力：`off`。用户于 2026-09-24 授权自动完成剩余 Phase 4–5，已到达 Phase 5 终点。

- “执行 Phase X”只执行指定阶段；“继续”先读取本计划，选择首个 `in_progress`，否则选择首个 `pending`。`manual` 模式下完成该阶段、更新并汇报后停下；依赖未满足时记录原因。
- 本计划存在后，只有用户另行明确要求连续多阶段执行，才能启用 `auto` 或 `auto_until`。先核对阶段范围与依赖并记录授权。`auto` 推进至完成或真实阻塞；`auto_until` 只推进记录的含端点范围。省略起点时从当前 `in_progress`，否则从首个 `pending` 开始；按阶段数描述的请求应换算成明确终点。单独点名一个阶段的命令只限制当次执行，不改变已保存模式。
- 自动选择每个阶段前，重读状态、依赖、模式和授权边界，先标记 `in_progress`。若终点阶段被拆分，默认完成其最后一个子阶段才到达终点，除非用户明确指定子阶段。`auto_until` 范围全部完成且必要的工作区返回已核验后，改回 `manual`、清空两个边界、记录到达终点并停下；交付受阻时保留原模式和范围。
- 用户侧可见检查默认记录为待办，仅在后续阶段实际依赖其结果时才阻塞。只有重大产品选择未定、验证失败且无安全的范围内修复、必须由人完成的操作或外部状态、新权限、用户中断等真实阻塞才暂停自动推进；为 `blocked` 阶段记录解除条件并在后续选择前复核。
- 仅当执行证据表明某阶段不能安全地一次完成时，才拆成尽量少的子阶段；先更新状态表、受影响的详情和验收清单，再动手实施。不要为形式整齐而拆分，也不要重编号其他阶段。
- 每执行完一个阶段，在对应实际完成记录和状态表写明文件、执行及跳过的检查、偏差、剩余风险和下一建议阶段，并按实际代码同步 `docs/overview.md`。计划或模型回复不等于实现证据。
- 不从本计划擅自改写基础裁剪计划的状态，不覆盖工作区既有改动；遵守仓库针对性测试、API、文档和 Desktop-only 规则。

## 关键路径日志

本阶段新增状态会决定请求可见的内容。以下 Host 路径应使用简短、结构化的诊断日志：Project/BotProfile 创建、修改和删除；Session 当前归属变更及历史提交；Agent 请求前解析当前项目/Bot 配置；拒绝模型路由；重启后恢复归属。记录 ID、版本、决策码和结果，不记录用户指定身份正文、提示词、文件内容、凭据、完整 Session、大型产物或高频流式片段。优先使用仓库现有 logger，并统一使用 `personal-bot` 或所属 package 的稳定标签。仅迁移期间需要的日志在对应阶段结束时移除；模型可见内容仍以 Session 事件为重建依据，诊断日志不能取代它。
