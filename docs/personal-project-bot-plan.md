# 个人项目与 Bot：产品路线图 Phase 2 开发计划

本文细化[产品路线图](../ai-native-work-os-product-roadmap.md)的 **Phase 2**。以后收到“继续”或“执行 Phase X”时，先读取本文，再依据唯一的阶段状态表执行。本文只记录规划，不表示 Phase 2 已开始实现。

## 目标与可行性

交付可用的个人 Desktop 模式：项目按目录组织对话；私人 Bot 提供可复用的工作方向、配置与获准能力；同一 Session 可同时从项目和 Bot 找到。用户继续控制模型和凭据配置。Bot 可以跨对话使用少量可检查、可纠正的记忆，但项目资料不会自动进入记忆。

现有 `dsh-workspace` 已持久化目录对应的 Workspace 及其 Session，`ui-workspace` 已提供项目式分组和会话状态；设置、凭据、模型选择、Session 事件及 Agent preset 也已有实现。因此下一阶段主要补齐 BotProfile 持久化、Session 与 Bot 的关联、运行时配置、受控记忆和第二个导航入口。无需另建一套 Session 存储或模型设置系统，技术上可行。

[基础裁剪计划](desktop-agent-foundation-pruning-plan.md)的 Phase 7 仍为 `in_progress`，当前未提交的 Desktop 清理改动需另行完成针对性验证。用户于 2026-09-24 明确取消 macOS/Windows 安装验收要求，并报告本地模型已能正常交互。这是用户报告的结果，不等同于助理运行过真实模型测试；未验证的浏览器、计算机操作、恢复和安装行为仍应如实标注。基础裁剪计划的剩余收尾不阻塞本计划的规划和实现。

## 范围、假设与约束

- **范围内：**个人项目对话导航、BotProfile 的创建/编辑/删除、Session 关联 Bot、模型/Skill/工具默认配置、少量显式记忆、项目与 Bot 双入口、复用现有模型设置、重启后保持数据，以及针对性验证。
- **范围外：**组织身份、共享项目、WorkGraph、跨对话任务接力、自动生成长期摘要、向量检索、外部 Agent 适配器、新模型供应商，以及公开 Web/CLI 入口。这些属于后续阶段。
- **项目身份：**本阶段用现有目录型 `Workspace` 作为个人项目的数据身份，保留其删除不清理目录和 Session、路径规范化等规则。如确需项目附加元数据，按 `WorkspaceId` 增加窄范围记录，不另建一套项目与会话归属表。
- **会话身份：**项目入口和 Bot 入口引用同一 `SessionId`、事件日志、标题、归档状态、运行状态和待处理状态。一个 Session 在本阶段最多关联一个 Bot；一个 Bot 可关联多个 Session。关联、解绑和切换入口均不复制 Session。
- **配置变更：**BotProfile 的修改从下一次获准的模型请求起生效；通过现有 Session 机制记录当次真正进入模型上下文的配置，旧请求仍可重建。删除 Bot 不删除其 Session 和历史，关联关系如何处理由 Phase 1 对照现有生命周期最终确认。
- **记忆：**仅用户明确添加或编辑的内容可持久保存。每条记录有来源、范围、更新时间及纠错/删除入口。项目资料、凭据、临时审批及未来的组织资料默认不写入私人 Bot 记忆。
- **模型：**复用 `ui-settings-models`、凭据服务和 `ui-model-selection`。Bot 默认模型只能引用已配置且允许使用的路由；BotProfile 不存 API key。
- **产品与验证：**Electron 是唯一用户入口。遵守 Host/Client 分层、UI 文案本地化、现行 Session 格式、跨边界品牌化 ID 和 package 能力接口。按用户要求，不启动页面，不使用 Playwright、浏览器自动化或 GitNexus；用户可自行检查可见的 Desktop 行为。

## 阶段详情

### Phase 1：数据与行为定稿

**目标：**在增加存储或 UI 之前，把路线图中的个人模式行为落实为明确的数据归属和状态变化规则。

**预计涉及：**本文、`docs/overview.md`，以及 Workspace、Session、preset、模型相关源码和 package 文档；仅在现有文档无法容纳决定时新增简短决策记录。

**验收清单：**

- [ ] 梳理现有 Workspace 归属、Session 创建/分叉/归档、Agent preset、模型选择、凭据存储和 Host/Client API 的责任方。
- [ ] 定义新 Session 如何选择项目与 Bot、Bot 修改何时作用于已有 Session、分叉是否继承关联、删除和解绑后的行为。
- [ ] 区分 Session 中应记录的模型可见配置与可修改的私人 Profile 引用，确保当前格式会话可重新打开并重建请求。
- [ ] 核对基础裁剪剩余改动与本阶段接口的重叠范围；不把用户免验的安装项目写成已通过。

**助理侧验证：**源码/API 审阅、Workspace 与 Session 的针对性现有测试、依赖映射检查。**用户侧人工检查：**若 Bot 编辑/删除或分叉语义与上述默认假设不同，审阅该决定。**依赖：**当前基础代码；基础裁剪收尾可并行进行。**实际完成记录：**尚未开始，执行后填写。

### Phase 2：BotProfile 与 Session 关联持久化

**目标：**私人保存 Bot 配置，使一个 Session 最多关联一个 Bot，且不复制 Session 数据。

**预计涉及：**合适的 `packages/` 分组中的 Bot Service Definition/Provider、存储域、Host Controller/API 投影、Desktop 组合和针对性测试；项目归属继续使用现有 Workspace registry。

**验收清单：**

- [ ] BotProfile 可创建、列出、重命名、编辑、删除，使用稳定的品牌化 ID；非法字段被拒绝，重启后数据仍在。
- [ ] Session 与 Bot 的关联以原子操作或明确的恢复流程持久化；拒绝未知/已删除 Bot，不产生重复 Session。
- [ ] 解绑/删除 Bot 后保留 Session 历史和项目归属；分叉与归档遵循 Phase 1 定稿规则。
- [ ] Bot 数据保存在个人存储中，凭据仍只进入现有凭据服务。

**助理侧验证：**存储恢复及生命周期、API 非法引用、相关 Session 重开、产品可见插件的真实组合测试和针对性 typecheck。**用户侧人工检查：**本数据阶段无必需项。**依赖：**Phase 1。**实际完成记录：**尚未开始，执行后填写。

### Phase 3：Bot 运行配置与默认模型

**目标：**让用户选中的 Bot 以可追溯、受限制的配置影响实际 Agent 工作。

**预计涉及：**Agent preset/请求入口的 Bot 消费方、现有模型设置与选择接口、工具/Skill 的实际授权入口及相关测试和文档。除非现有扩展点确实不足，不修改 `agent-loop`。

**验收清单：**

- [ ] Bot 默认模型只解析到已配置、可用的路由；Session 显式选择的优先级有明确规则，无法使用时显示错误，不静默回退。
- [ ] Bot 指令和允许的 Skill/工具在实际执行入口生效，直接调用或其他入口不能绕过限制。
- [ ] 进入模型请求的有效配置先记录在 Session 中；重开或分叉后仍可重建历史请求。
- [ ] Profile 编辑只影响之后获准的请求，不改写旧请求，也不泄露 API key。

**助理侧验证：**真实组合下的模型请求、执行入口拒绝、Session 重放/重开、不可用模型路由测试；有密钥时可补真实 API smoke。**用户侧人工检查：**可自行在 Desktop 中选择模型并进行一次受控 Bot 对话；该结果不写成助理测试。**依赖：**Phase 2。**实际完成记录：**尚未开始，执行后填写。

### Phase 4：显式、可纠正的 Bot 记忆

**目标：**让用户保留少量可复用事实，并能检查来源、修改或删除。

**预计涉及：**Bot 记忆存储/服务、受控请求上下文贡献、Host API、最小编辑入口或 Phase 5 的 Bot 设置界面及测试。

**验收清单：**

- [ ] 每条记忆记录来源、范围、更新时间和大小限制，并提供编辑/删除；只有用户明确操作才持久保存。
- [ ] 项目消息、引用文件、凭据、审批及未来组织记录不会自动进入记忆。
- [ ] Bot 请求只使用符合范围的记忆，总请求开销有上限，模型可见内容记录在 Session 中。
- [ ] 纠正或删除后不再影响后续请求，同时保留过去请求的可重建性。

**助理侧验证：**自动写入拒绝、范围、大小上限、编辑/删除、重启和 Session 重放测试。**用户侧人工检查：**编辑界面完成后，可自行检查和纠正一条记忆。**依赖：**Phase 3。**实际完成记录：**尚未开始，执行后填写。

### Phase 5：项目与 Bot 双入口

**目标：**让两个入口通向同一个 Session，显示一致的关联和状态。

**预计涉及：**`packages/client/ui-workspace`、侧边栏/导航 slot、Bot UI 插件、本地化字典、Host follow 投影和针对性 Client 测试；复用现有模型设置界面。

**验收清单：**

- [ ] 项目入口展示对话及现有运行/待处理/完成状态；Bot 入口通过同一 `SessionId` 列出关联对话。
- [ ] 从任一入口打开关联 Session，不复制消息、Run、归档或未读状态；刷新和重启后两处仍引用同一记录。
- [ ] 界面清楚显示并可编辑 Bot 关联和有效的 Bot/模型选择，文案进入本地化字典。
- [ ] Bot 创建/编辑/删除、记忆纠正有可访问的操作；删除 Bot 后仍可从项目或未分组入口找到原 Session。

**助理侧验证：**纯 Client/Host 投影测试、同 ID 状态更新、归档/删除/重启、locale 与可访问性静态检查、typecheck 和前端 build。**用户侧人工检查：**可自行检查 Desktop 双入口和编辑流程；助理不打开页面或运行 Playwright。**依赖：**Phase 2–4。**实际完成记录：**尚未开始，执行后填写。

### Phase 6：Phase 2 集成验收

**目标：**用可复核证据收尾路线图 Phase 2 的持久化、模型使用及 Desktop 展示行为。

**预计涉及：**集成测试/夹具、package README、`docs/overview.md`、本文；只有证据支持时才更新路线图状态。

**验收清单：**

- [ ] 创建项目和 Bot、启动一条关联 Session，从两个入口找到相同 ID；运行及重启后仍保持同一会话和状态。
- [ ] 第二条 Bot 对话使用获准的 Profile 默认配置与用户批准的记忆；未明确添加的项目资料不进入记忆。
- [ ] 删除或编辑 Bot 后历史 Session 保留，后续运行行为正确，过去日志不变。
- [ ] 基础裁剪遗留清理已针对性验证，或其未完成项有准确记录；用户取消的 macOS/Windows 安装验收不作为 Phase 2 完成门槛，也不写成已通过。
- [ ] Phase 2 文档只描述已实现代码，明确区分后续 Phase 3 的任务接力与 Phase 4 的组织功能。

**助理侧验证：**针对性真实组合测试、构建后的 Host/Desktop 路径 smoke、相关 typecheck/lint/build/文档检查和 `git diff --check`；若已配置密钥可做真实 API smoke，不默认跑全仓测试。**用户侧人工检查：**可自行检查可见 Desktop 交互；无 macOS/Windows 安装验收硬门槛。**依赖：**Phase 1–5。**实际完成记录：**尚未开始，执行后填写。

## 后续执行规则

执行模式：`manual`。自动开始阶段：`none`。自动停止阶段：`none`。跨对话自动接力：`off`。当前是计划修订，尚未授权开始 Phase 1 实现。

- “执行 Phase X”只执行指定阶段；“继续”先读取本计划，选择首个 `in_progress`，否则选择首个 `pending`。`manual` 模式下完成该阶段、更新并汇报后停下；依赖未满足时记录原因。
- 本计划存在后，只有用户另行明确要求连续多阶段执行，才能启用 `auto` 或 `auto_until`。先核对阶段范围与依赖并记录授权。`auto` 推进至完成或真实阻塞；`auto_until` 只推进记录的含端点范围。省略起点时从当前 `in_progress`，否则从首个 `pending` 开始；按阶段数描述的请求应换算成明确终点。单独点名一个阶段的命令只限制当次执行，不改变已保存模式。
- 自动选择每个阶段前，重读状态、依赖、模式和授权边界，先标记 `in_progress`。若终点阶段被拆分，默认完成其最后一个子阶段才到达终点，除非用户明确指定子阶段。`auto_until` 范围全部完成且必要的工作区返回已核验后，改回 `manual`、清空两个边界、记录到达终点并停下；交付受阻时保留原模式和范围。
- 用户侧可见检查默认记录为待办，仅在后续阶段实际依赖其结果时才阻塞。只有重大产品选择未定、验证失败且无安全的范围内修复、必须由人完成的操作或外部状态、新权限、用户中断等真实阻塞才暂停自动推进；为 `blocked` 阶段记录解除条件并在后续选择前复核。
- 仅当执行证据表明某阶段不能安全地一次完成时，才拆成尽量少的子阶段；先更新状态表、受影响的详情和验收清单，再动手实施。不要为形式整齐而拆分，也不要重编号其他阶段。
- 每执行完一个阶段，在对应实际完成记录和状态表写明文件、执行及跳过的检查、偏差、剩余风险和下一建议阶段，并按实际代码同步 `docs/overview.md`。计划或模型回复不等于实现证据。
- 不从本计划擅自改写基础裁剪计划的状态，不覆盖工作区既有改动；遵守仓库针对性测试、API、文档和 Desktop-only 规则。

## 关键路径日志

本阶段新增状态会决定请求可见的内容。以下 Host 路径应使用简短、结构化的诊断日志：BotProfile 创建/修改/删除及 Session 关联/解绑提交；Agent 请求前解析 Bot 配置；拒绝模型路由；记忆新增/修改/删除和范围拒绝；重启后恢复关联。记录 ID、版本、决策码和结果，不记录记忆正文、提示词、文件内容、凭据、完整 Session、大型产物或高频流式片段。优先使用仓库现有 logger，并统一使用 `personal-bot` 或所属 package 的稳定标签。仅迁移期间需要的日志在对应阶段结束时移除；模型可见内容仍以 Session 事件为重建依据，诊断日志不能取代它。
