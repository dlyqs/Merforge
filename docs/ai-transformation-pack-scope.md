# 内置 AI Transformation Pack：M5–M8 交付边界

## 定位与进入条件

2026-09-15 补充后续产品合同，未实现、未授权执行。里程碑状态见 [roadmap](roadmap.md)。本 Pack 是首个内置垂直 Agent 能力集合；M5 交付可用内置能力不以 M8 的通用 Pack SDK 为前提。其角色可以共享成熟 Agent Runtime，不意味着现在创建多个独立 Agent 服务。

M5 以 M4 的自然语言规划、双端交互、审阅和执行器契约为基础；M6 进一步执行 M5 的改造计划。首期限定一个软件密集型数字业务流程。自动生产上线、复杂 ERP 写操作、全公司自主改造和高风险自动决策不纳入首期验收。

## 用户完整流程

在 CLI 菜单或 GUI 对话选择“企业 AI 转型” → 描述业务问题并提供 SOP/资料 → 领域访谈澄清 → 确认现状流程、角色、系统、数据、政策与指标 → 评估改造单元和方案 → 审阅目标状态/差异/ROI 假设 → 确认实施任务与业务验收 → 在 M6 显式启动实施 → 工程验收、集成和业务评估 → 交付可追溯报告。

M5 结束于“可审阅、可实施的方案与任务”；M6 才以真实改造结果验收。用户原始资料、LLM 推断、人工确认和实测结果必须分开标记。

## 分阶段交付与交互

**M5：内置规划 Agent MVP。** CLI 支持领域选择、资料提供、访谈问答、确认事实、方案审阅和任务导出；GUI 提供聊天式 Discovery，加上可检查的流程/角色/系统/数据及改造单元视图。结构化表格/列表可作为首版，不要求先做完整可拖拽企业图。资料导入明确支持格式、大小、来源与访问权限，不默认接入所有企业系统。至少一条真实流程从原始资料走到结构化方案和任务；有缺资料/不适合 AI 的负例，不能只交付静态示例提示词。

**M6：真实改造落地。** CLI/GUI 沿用 M4 的审阅、模式、执行和恢复入口，增加工程进度与业务验收视图。至少一个经授权的真实案例完成实际代码/流程改造、独立工程检查、集成和业务评估；必须区分本地/测试环境、业务验收与生产上线。没有生产部署也可完成约定的试点验收，但不能声称已上线。需要外部系统/测试数据时，在实施前明确访问方式、人工职责与成功指标。

**M7：证明效果。** 在固定任务和环境比较直接 Agent、Agent+Skill、Merforge，分开记录规划质量与实施效果、执行/验收耗时、重试、人工介入和可得用量。单案例通过不等同普遍 ROI 或企业规模验证。

**M8：扩展。** 从已用起来的内置 Pack 抽取稳定契约、开发说明和评估接口，再通过第二 Pack 验证可复用性；不提前搭建空的插件市场或通用领域框架。

## Core / Pack 合同

Core 管任务身份、计划版本、审批、执行授权、调度、Attempt、工作区、证据和恢复；Pack 管访谈策略、企业领域 schema、评估逻辑、业务政策、案例和业务验收规则。CLI/GUI 通过统一 API 展示领域产物与工作状态，不绕过 Core 直接操作执行器或数据库。

领域资料与 LLM 输出均按数据处理；其中出现的命令或指令不构成操作授权。每条建议/任务关联原始来源、假设或人工确认。资料变化后标记受影响模型/评估/计划需重新确认，不静默修改已执行定义。领域 schema 与迁移在 M5 实施前确定，只按实际需要扩展，不现在创建空包或大一统 schema。

各里程碑开始前需基于真实样例拆详细阶段，列出资料、执行环境、业务验收人/规则与权限依赖。资料或环境缺失不得用虚构企业内容填充验收；可以继续独立的准备工作，但对应真实场景保持未完成。
