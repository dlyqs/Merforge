# M3 阶段执行计划：首个真实 Executor

## 目标与执行入口

将 M2 的可控串行任务接到真实 Codex：已审阅的 Task Package → 受控 Git 工作区 → Codex 执行 → 产物快照 → 独立命令验收 → 持久化完成；中断后先核对进程和工作区，再显式恢复。目标属于 large goal，本文是 M3 唯一阶段状态与后续执行合同。

依据：[roadmap](roadmap.md) 的 M3，以及根目录 [v0.1 开发说明](<../Merforge v0.1 — 开源 Agent Orchestration Framework & AI Transformation Agent 开发说明.md>) 第 6、7、13–19、25、27–28 节。代码导航见 [overview](overview.md)。M3 对应原说明 Phase 2 和 Phase 4 的确定性验证子集，不包含完整多执行器/Planner 闭环。

- execution mode: manual
- automatic start phase: none
- automatic stop phase: none
- conversation relay: off
- plan review: pending
- execution authorization: none（2026-09-14 仅编制阶段执行文档）

本计划的开发模式与 Merforge 产品中用户计划的执行模式分开管理。M2 的自动执行和新任务接力授权止于 M2，不能继承到本计划。暂不创建专用执行 Skill；后续明确“执行 M3 Phase X”或在本计划语境下“继续”时，先读本文和 overview，并核对进入门禁。

本机 `/opt/homebrew/bin/codex` 报告 `codex-cli 0.120.0`；`codex exec --help` 列出非交互执行、`--json`、工作目录、sandbox、输出 schema 及 resume 子命令。本次仅调用 version/help，未登录、读取凭证、调用模型或验证真实协议。帮助命令有 PATH 更新权限警告，但成功退出。不能据此声明认证、sandbox 或恢复已经可用。

可行性有条件成立：SQLite/事务/审批/调度可复用，先接 CLI 子进程比引入完整会话服务更小。硬风险是实际登录与网络可用性、CLI 事件版本差异、daemon 崩溃后遗留进程、工作区漂移和不可信验收命令。Phase 1 必须用可复现证据确定支持范围；真实调用不可用时保留阻塞和解除条件，不能用模拟测试完成 M3。

## 范围、必要调整与技术决策

| 项目         | 本计划的决策与理由                                                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Adapter 路径 | 首选本地 `codex exec` JSONL；先实测再固定受支持版本/事件契约。不同时实现 SDK、app-server、桌面任务调用三套通道。若 CLI 不满足硬要求，记录具体缺口并修订受影响阶段后再换路径。    |
| M2 缺口      | 留在 M2 原计划完成，避免重复实现恢复屏障和计划 CLI。M3 在已验收基础上增加真实进程/文件核对。                                                                                     |
| 恢复承诺     | 保证任务身份、证据和执行边界持久化；会话恢复仅在对应 CLI 版本实测支持时启用。明确区分同会话续跑、新 Attempt 重试和仅核对产物，不承诺恢复任意代码位置或外部副作用恰好一次。       |
| 工作区粒度   | 每个代码 Plan revision 关联独占、受管 Git worktree，串行任务共享以继承前序产物；每次 Attempt 保存输入/输出快照。M3 暂不为每 Task 开分支后再实现自动合并。                        |
| 验证优先     | 命令/测试由独立 Verifier 执行；Agent 输出、正常进程退出和非空 diff 都不能单独判 PASS。验收定义在审阅前固定，执行后不能降低标准。                                                 |
| 状态扩展     | 优先保留 Task 七状态；取消确认后以 interrupted 和固定原因码区分，失败为 failed。工作区核对状态单独保存，未确认进程停止不能解锁/重试。不为本节点扩展全套 RETRY/BLOCKED 验证协议。 |
| 演示边界     | M3 完成至少三阶段真实代码演示、到界停止、中断核对和失败样本；原说明五/七阶段及多执行器长目标综合演示仍由 M4 承接。                                                               |

**包含：** 版本化 Task Package；Codex start/events/cancel 和经核实的 resume；受管工作区；持久化进程/会话关联；diff/文件清单/日志证据；命令验收；显式恢复/重试；API/CLI 与最小 Web 展示；真实样例和 M7 所需原始指标。

**不包含：** Claude/Generic、多执行器自动选择、智能 Planner、动态拆任务、DAG/并行、自动修复循环、对运行中 Agent 实时 send/steer、业务 Pack、LLM Judge、成本优化平台、远程 Worker、生产隔离平台、自动合并/推送/部署。未知能力明确 unsupported，不为未来功能预建空包。

## 实施契约与约束

1. **技术与兼容：** 保留 TS/Zod/SQLite/Fastify/Commander/React、轮询和本地单 daemon。Runtime 不依赖 HTTP/UI；CLI/Web 只经 API。只追加数据库迁移；保留 M1 单任务与 plan.v1 历史解析。新代码任务使用显式新版计划/验收 schema，不把旧 summary.v1 的 PASS 改称代码验收。新增迁移编号依据执行时实际数据库版本分配。
2. **Task Package：** 建议新增 `task-package.v1`，包含 schemaVersion、goal/plan/revision/phase/task 引用、目标与具体指令、输入内容或不可变引用/hash、预期文件/产物、允许/禁止改动范围、workspace 引用、验收规则及版本/hash、执行策略。审阅覆盖这些语义字段；运行配置只可由本地操作者设定。Attempt 记录 packageHash、输入快照、adapterVersion、模型标识（可得时）和执行关联。不要把本机路径、会话 ID 混成可移植业务定义。
3. **冻结与身份：** 沿用 M2 执行后计划定义冻结；修改目标/验收需要新计划，不能偷偷改已批准 Package。任务 ID、Attempt ID、会话 ID、工作区 ID 各自独立。重试/恢复执行创建新 Attempt，并保存前驱关联；同会话不复用旧 Attempt 判定。旧实例/旧 Attempt 结果不能覆盖当前状态。
4. **工作区：** 从明确的干净 Git 基线创建受管 worktree，记录源仓库、解析后的 commit、工作区真实路径与归属。拒绝未知/脏源工作区自动接管，不清理用户文件。限制受管根目录、路径穿越和符号链接逃逸；worktree 不是安全沙箱，不能宣称隔离任意恶意代码。共享同一工作区的不同 Plan/daemon 也必须互斥，数据库单 Plan 限制不足以保护文件。
5. **串行继承：** 后继任务只使用前序 PASS 对应的持久化输出快照；保留未提交改动而不自动提交。输出记录完整受管文件清单/hash及 diff，覆盖新增/删除/重命名、未跟踪文件和有界二进制证据，不能只用 `git diff` 漏掉新文件。启动下一 Attempt 前核对上次输出，外部漂移则阻塞，不覆盖、不 reset。
6. **进程与 I/O：** 先提交 Attempt/工作区占用，再派发进程；记录派发 token、PID/进程组、启动身份、sessionId（可得时）。使用可执行文件加参数数组和 stdin，不拼 shell 字符串。超时、取消、退出、stderr 与 JSONL 分别处理；设置行长/总量/运行时限，输出异常有原因码。环境只传必要项；不更改用户全局 Codex 配置，不默认绕过 sandbox，不把本计划批准等同于任意联网或外部写操作许可。
7. **证据与验收：** Artifact 大内容保存到受管证据目录，SQLite 保存相对引用、hash、大小、类型和归属。采用临时写入后原子发布，再提交引用；残留可核对且不误完成。检查定义/测试基准保存在 Agent 写入范围外；若验收运行仓库脚本，绑定审阅时的脚本及配置，检查篡改并要求独立断言，防止通过把 test 脚本改为 exit 0 获得 PASS。命令限定 cwd、argv、环境、时限及输出上限，只运行已审阅检查。M3 限受信任本地样例，不承诺任意不可信代码的安全执行。
8. **产物绑定：** Verifier 在对应冻结快照或受排他保护的工作区运行；验证前后核对受保护源码与规则 hash，构建产生的允许输出需预先声明。所有必需检查实际执行且通过才 PASS，缺证据/超时/规则不支持都不能 PASS。重启重放仅限声明可重复执行的本地检查，其他情况要求显式核对，不能盲目重放任意 shell 副作用。
9. **恢复与取消：** 恢复屏障先完成 M2 状态核对，再验证工作区归属、进程身份、文件快照及证据完整性，最后重新检查审批/模式/范围。daemon 的数据库锁释放不代表 Agent 已退出；存活或无法确认身份时隔离工作区并停止派发。取消请求先持久化，确认受管进程树停止后才终结 Attempt。禁止仅凭 PID 杀进程，禁止后台自动重跑 interrupted 工作。
10. **用户限制：** 不拉起页面，不用 Playwright/浏览器工具或相关 Skill，不用 GitNexus、不自行派生子代理或新任务。前端检查用类型/构建/接口/可独立测试逻辑。仅临时数据库和专用样例仓库做破坏性回归；不提交、推送或部署。用户视觉检查可选，未做不能写通过。

## 关键链路可观测性

沿用注入的 Runtime logger，结构化 `component` 使用 `merforge.runtime`，可扩展 `merforge.executor.codex` / `merforge.verifier`。公共字段按存在性携带 goalId/planId/revision/phaseId/taskId/attemptId/workspaceId、event、errorCode、durationMs；会话引用只存必要元数据。

Phase 2 记录 Package 绑定与拒绝；Phase 3 记录工作区所有权/快照/证据发布；Phase 4 记录进程派发、退出、超时、取消确认；Phase 5 记录检查结果与验证终态；Phase 6 记录恢复分支/漂移/拒绝；Phase 7 确认一组关联 ID 能串起演示。状态和业务事件同事务，大量流式日志在事务外有界存储。

这些是长期诊断线索。不要记录凭证、完整环境、认证响应、完整 Prompt/源码大块内容或每 token 事件；命令输出可能含敏感信息，保存前脱敏且限制大小。读取证据须验证归属/路径，不把终端转义或 HTML 输出直接解释为可执行内容。日志写入失败不得改变已提交状态，但必需产物写入失败必须阻止 PASS。

## 后续执行规则

1. 执行前读取本文、overview、适用用户/仓库约束和 M2 门禁，检查实际工作区变化。首版审阅未通过不实施；明确“执行 Phase 1”可作为审阅后的单阶段授权并记入顶部。未授权子代理或接力，不创建新任务。
2. `manual` 下“继续”选择首个 in_progress，否则首个 pending；先复核相关 blocked 的解除条件，未解决则报告精确依赖，不能绕行。单阶段执行完成后更新记录并停止。
3. 任何明确单阶段命令只执行该阶段，即使持久模式为自动也仅限制本轮；后续“继续”再按保存模式执行。指定阶段不能跳过不可隔离的前置依赖。
4. 计划存在后，用户明确“自动完成全部阶段”才可切 `auto`；“自动执行到 Phase N”切 `auto_until`。先校验顺序/依赖并记录授权原文；省略起点取首个 in_progress，否则首个 pending，数量表达按主表转为具体包含两端的范围。无效范围不改变模式，询问唯一缺失边界。
5. `auto` 的两端为 none；`auto_until` 只选授权范围内未完成项，每次自动选阶段前重读状态、依赖、模式和边界，先标 in_progress。连续执行不逐阶段询问。
6. `auto_until` 整个范围完成后切 manual、清两端为 none、记录到界并停止；范围已全部完成也不重跑。不能因终点完成而忽略范围内未完成工作。
7. 自动执行遇到真实产品歧义、无法替代的人工作业/外部环境、新权限或无安全修复路径的失败时标对应阶段 blocked，记录原因和解除条件，保留模式与范围；解除后沿用授权。可选视觉检查只记录，不能自动阻断后续。
8. 仅当执行证据说明某阶段过大/风险过高/无法一轮验证时，将该阶段最小拆成通常两个子阶段。先更新主表、详情、验收和依赖顺序再实现；保留后续编号。授权停止于原阶段时，以其最后子阶段为界；明确指定子阶段则在该子阶段停。
9. 每阶段完成后在其实际完成区记录具体改动/文件、检查命令与结果、跳过项、偏差/风险和下一阶段；同步主表与 overview。架构/命令改变时同步 architecture/README，里程碑变化时同步 roadmap，不新增重复全局进度记录。
10. relay 保持 off；自动模式不授予新任务接力、部署、推送、生产写入或范围外行为。重大范围变化先形成可审阅修订；不把原开发说明中的长期愿景扩大成本节点交付。
