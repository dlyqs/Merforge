# 个人工作流 Desktop 验收剧本

此剧本验证[个人工作流](personal-workflow.md)的用户交互。施工 Phase 7 的无页面自动化检查不等同于此处的可见验收。状态：2026-09-25 待用户执行；真实模型自然语言分类也尚未验证，当前环境及根 `.env` 无 `DEEPSEEK_API_KEY`。

## 准备

使用 Desktop，在一个可丢弃的本地目录新建 Project。准备有模型配置的普通对话，并另建一个允许内置 `dev-workflow` Skill 的 Bot 对话。保留其他工作目录不动。测试产物分别声明为 `contract.json`、`export.mjs`、`rows.json`、`result.csv`、`delivery.txt`；不要求自动隔离工作区。

验收记录应包含执行日期、应用版本、模型、计划 ID/版本、任务 ID、Run、接力前后对话、结果和失败现象。不要附带 API key 或本机其他私人文件。

## 普通与增强模式

1. 在普通 Project 对话关闭增强模式，发送“给出 name、note 两列的 CSV 表头”。应直接回答，不出现必须审核的计划或执行记录。
2. 开启增强模式，重复简单目标。应仍可直接完成，不强制建立任务树。关闭并重开对话后确认开关的最后选择已保存。
3. 在 Bot 入口重复前两步。确认仍使用选定 Bot 的身份、工具和 Skill 许可；双入口不复制对话或任务。
4. 在测试 Bot 禁用该 Skill 后开启增强模式，应明确反馈许可限制。恢复许可后再继续。

## CSV 计划与审核

在增强对话发送：“实现 CSV 导出，先澄清字段、转义和换行规则，再拆分接口约定、导出实现、独立测试数据准备和集成验收；实现与数据准备可以并行。”澄清时指定 `name,note` 列、LF 换行、逗号/双引号字段加引号且内部双引号加倍。

审阅树、阶段和依赖：根任务 CSV 交付有四个必要子任务；接口约定先行，实现和数据准备各自依赖接口约定，集成依赖这两个分支。根任务还需独立交付检查。父子树不应制造两个分支之间的依赖。

确认目标、目录、产物、验收和版本后批准。批准不发送消息、不执行工具。修改验收再保存应形成新版本，旧批准失效；对新版本重新审核。导出的 Markdown 与当前版本一致，修改导出文件不改变应用内批准。

## 用户选择、并行与接力

1. 新开执行对话，在输入框任务下拉选择接口约定，使用默认 manual。选择仅绑定；发送消息后才执行。完成证据应关联本任务和 Run。
2. 接口完成后分别新开两个对话，为导出实现和独立数据准备选择任务。集成任务仍不能被选中。两条对话分别发送执行请求，检查状态可以同时运行；同一任务不能被第二条对话重复领取。
3. 暂停导出实现，对它发起接力。若工具仍在途，待结果收敛后重试；新接收对话保持暂停，须显式恢复并发送消息。旧对话不能再执行本任务。数据准备对话应继续，不因兄弟任务接力而暂停。
4. 检查接收者保留同一 Task/Run、批准版本、决定/待办、原停止位置和累计预算，以及原对话链接。重复点击或重试同一接力不创建额外接收者。
5. 两个分支完成后，集成任务出现在候选列表，但不自行创建对话或运行。用户另开对话选择并执行集成；根任务仍需自身验收和交付证据。

测试数据至少包含 `Alice / hello,world` 和 `Bob / say "hi"`。用户从目录独立读取最终文件，期望内容如下，末尾有一个 LF：

```csv
name,note
Alice,"hello,world"
Bob,"say ""hi"""
```

## 停止、恢复与拒绝

- 选择 auto_until 时使用明确阶段和较小推进预算。到界暂停，只作用于已选任务；不领取下一个任务，也不创建下一条执行对话。接力不得刷新预算。
- 在可丢弃任务执行期间退出并重启 Desktop。未完成运行进入待核对，不能自动重放未知工具动作；检查实际文件后填写核对说明再恢复。未知动作本身不能作为成功验收证据。
- 暂停后修改该任务声明的产物，再尝试无说明恢复或接力。应要求核对，不能静默覆盖。兄弟任务正常写入其已声明产物不应令整个计划失效。
- 尝试保存自依赖/依赖环，应该拒绝；旧版本审核、候选过期、重复领取应提示原因并刷新。取消一个任务不取消兄弟任务；取消后迟到的结果可保留，但不允许新动作。

## 自动化证据范围

`apps/desktop-host/tests/personal-workflow.spec.ts` 通过测试用 `cordis.yml` 和真实 Loader 组合持久存储、个人配置、Skill、AgentLoop、工具、Session Controller 和 Gateway；模型响应使用确定性适配器，CSV 工具写入真实文件，集成通过独立 Node 子进程运行导出代码并由测试读取校验。它不启动 Electron 窗口，不声称测试了完整 Desktop 进程启动或自然语言分类质量。

该测试覆盖 Project/Bot 简单目标、CSV 澄清和提案、准确版本审核、输入框所用 Remote 领取、两分支重叠、运行中兄弟任务与接力、重复移交、旧所有者拒绝、手动选择汇合、父任务独立证据和 Session 日志。包级测试补充依赖环、过期批准、领取竞态、自动停止、重启、权限、工作区变化和迟到结果；Client 测试检查纯交互逻辑。构建后 `node packages/workspace/personal-workflow/tests/built-smoke.mjs` 检查发布 JS、生成 Remote codecs、持久化重开与包内 Skill。

运行时不变量：工作流状态和所有权均来自单个原子计划记录，Client 从同一投影渲染，Skill 在操作时检查原记录；没有需要额外 companion 对账的独立副本。文件允许在执行中合法变化，指纹在核对动作中检查。各包 README 记录省略 companion 的原因；现有 storage-domain 的持久/缓存不变量由测试顶层门禁执行。

## Agent 顺序阶段与自动接力

1. 在输入框打开“执行模式”上拉面板，通过 Switch 关闭/开启自动规划，并在面板直接选择“Agent 顺序阶段”。检查设置页与面板偏好同步；重启后确认本机偏好保留，当前对话开关单独保留。
2. 提交一个确实需要至少六个工程阶段的需求。确认生成平铺的阶段列表，每个阶段有范围、验收、产物及显式前置，没有为限制五个子节点而添加中间分组。
3. 审核准确版本，打开“执行任务”，确认面板从按钮上方展开，直接显示就绪任务卡片，点击第一个阶段。推进方式默认手动，两个阶段设置已显示但禁用；选择“执行至阶段”，在“自动执行到某个阶段”选 Phase 2，再绑定并发送执行指令。确认 Phase 1/2 分别留下证据，进度显示“已完成至 Phase 2”，Phase 3 未启动。
4. 在同目录新对话选择后续就绪阶段，确认阶段卡片仍显示完成至 Phase 2。选择自动完成剩余阶段，在“每轮对话可执行多少阶段”选择“每轮 2 个阶段”，每完成两个阶段换新对话。确认新对话保留模型、原始指令、前序成果和剩余预算，旧对话不能继续执行；最终还须留下整体验收证据。
5. 在中间阶段暂停/取消，或在接力前重启 Host。确认不会自动重放工具动作，继续前需核对恢复。用原生 Codex 重复阶段推进及接力，确认接收者仍为 Codex 后端。

6. 缩短阶段范围，确认每轮阶段数不超过范围长度；选择“全部阶段 · 同一对话”后不产生自动接力。最终阶段完成后，整体验收单独显示，phase 完成数量不多计。
7. 用 Tab 在面板控件之间移动，用方向键操作阶段选择和数字预算；Escape 关闭并回到按钮。缩小窗口，确认上拉面板位于输入框上方，内容可滚动且绑定操作保持可见。
